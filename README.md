# მომხმარებელთა მიმართვების დამუშავება

AI სტაჟირების შესარჩევი დავალება.

პროგრამა ასუფთავებს `requests.json`-ს, USD/EUR თანხებს ლარში გადაიყვანს საქართველოს ეროვნული ბანკის (NBG) API-ით და Google Gemini API-ით თითოეულ მიმართვას ანიჭებს ერთ კატეგორიას (ზარალი / საჩივარი / ინფორმაციის მოთხოვნა / სხვა).

## 1. დაყენება და გაშვება

საჭიროა Python 3.9+.

```bash
python -m venv venv
venv\Scripts\activate            # Windows (macOS/Linux: source venv/bin/activate)
pip install -r requirements.txt
```

Gemini API გასაღები უფასოდ მიიღება Google AI Studio-ში: https://aistudio.google.com/apikey

```bash
set GEMINI_API_KEY=თქვენი_გასაღები          # Windows (cmd)
$env:GEMINI_API_KEY="თქვენი_გასაღები"       # Windows (PowerShell)
export GEMINI_API_KEY=თქვენი_გასაღები       # macOS / Linux

python main.py
```

გასაღების გარეშეც ეშვება: ამ შემთხვევაში `category` იქნება `null`, დანარჩენი ნაწილები კი იმუშავებს.

არჩევითი პარამეტრები: `--input` (ნაგულისხმევია `requests.json`), `--output-dir` (ნაგულისხმევია `.`), გარემოს ცვლადები `GEMINI_MODEL` (ნაგულისხმევია `gemini-3.5-flash`) და `LLM_CALL_DELAY` (პაუზა LLM-ის გამოძახებებს შორის, წამებში; ნაგულისხმევია `6`).

შედეგი: `processed.json`, `rejected.json`, `summary.json`.

### სტრუქტურა

| ფაილი | დანიშნულება |
|---|---|
| `main.py` | შესასვლელი წერტილი, ნაწილების დაკავშირება |
| `cleaning.py` | მონაცემების ვალიდაცია და გასუფთავება (ნაწილი 1) |
| `nbg.py` | NBG კურსების API, ქეში, ხელახალი ცდები (ნაწილი 2) |
| `llm.py` | კლასიფიკაცია Gemini-ით (ნაწილი 3) |
| `stats.py` | `summary.json`-ის სტატისტიკა |

## 2. გასუფთავებისას მიღებული გადაწყვეტილებები

პრინციპი: თუ ჩანაწერის სწორ მნიშვნელობას დავადგენ, ვასწორებ და `processed.json`-ში `fixes` ველში ვწერ, რა შეიცვალა. თუ ვერ დადგინდება, ჩანაწერი გამოირიცხება და `rejected.json`-ში ჩაიწერება რადგან მნიშვნელობას ვერ ვხვდებით, რადგან არასწორი მონაცემებია.

| ველი | გასწორდება | გამოირიცხება | დასაბუთება |
|---|---|---|---|
| `id` | ზედმეტი space იჭრება | არ არის მითითებული; განმეორებული id-ის მეორე ჩანაწერი | id უნიკალური იდენტიფიკატორია; დუბლიკატი ორჯერ დაითვლიდა მიმართვას |
| `date` | `15.02.2025`, `2025/02/15`, `2025.02.15`, დროის ჩანაწერები -> `YYYY-MM-DD` | არ არის მითითებული, არარსებული (`2025-02-30`), მომავლის თარიღი, უცნობი ფორმატი | `DD.MM.YYYY`-ში დღე პირველია (ქართული/ევროპული წესი). თარიღზეა დამოკიდებული თვის სტატისტიკა და კურსი |
| `channel` | case და space, `e-mail` -> `email` | `web/email/call`-ის გარეთა მნიშვნელობა | დასაშვები მნიშვნელობები დავალებაშია განსაზღვრული |
| `text` | space იჭრება | ცარიელი ან არ არის მითითებული | ტექსტის გარეშე კლასიფიკაცია შეუძლებელია |
| `amount` | სტრიქონი -> რიცხვი (`1,250.50`, `1.250,50`, `12,5`) | არ არის მითითებული, უარყოფითი, არარიცხვითი | უარყოფითი ან გამოტოვებული თანხა აზრს კარგავს. ნული დასაშვებია (მაგ. ინფორმაციის მოთხოვნას თანხა არ ახლავს); საშუალო ორივე ვარიანტითაა გამოთვლილი: ნულებით და ნულების გარეშე |
| `currency` | case (`usd` -> `USD`), სიმბოლოები (`$`, `€`, `₾`) | `GEL/USD/EUR`-ის გარეთა კოდი | უცნობი ვალუტის ლარში გადაყვანა შეუძლებელია |

## 3. სირთულეები და მათი გადაჭრა

> **3. სირთულეები და მათი გადაჭრა პროექტის ერთ-ერთი მთავარი სირთულე Google Gemini API-ს გამოყენება იყო, რადგან მასთან მუშაობა პირველად მომიწია. გამიჭირდა API გასაღების სწორად დაყენება, პროგრამასთან დაკავშირება და მოდელის გამართულად გამოძახება. ამ საკითხების გადასაჭრელად გავეცანი API-ს გამოყენების წესებს და ეტაპობრივად დავტესტე მისი მუშაობა. ასევე გავითვალისწინე მოთხოვნების რაოდენობის შეზღუდვები და დავამატე მოთხოვნებს შორის პაუზა, რათა თავიდან ამეცილებინა დროებითი შეცდომები. პროექტზე მუშაობისას ასევე გავიხსენე და უკეთ შევისწავლე JSON ფორმატთან მუშაობა და მიღებული მონაცემების დამუშავება.**

- თავდაპირველად გავეცანი, რა არის API გასაღები (API Key), რისთვის გამოიყენება და როგორ ხდება მისი მიღება და გამოყენება.
- მოვიძიე Gemini API-ის უფასო ვერსია, შემდეგ კი მისი პროექტში დანერგვისთვის ვუყურე სხვადასხვა YouTube ვიდეოს და დამატებითი ინფორმაციის მისაღებად გამოვიყენე AI ხელსაწყოები.
- JSON ფორმატთან მუშაობის გასაუმჯობესებლად დამოუკიდებლად შევასრულე რამდენიმე დამატებითი დავალება, რათა უკეთ მესწავლა JSON მონაცემების წაკითხვა, დამუშავება და მათთან მუშაობა.

## 4. შესწავლილი საკითხები და გამოყენებული წყაროები
- პროექტზე მუშაობისას გავიუმჯობესე JSON ფორმატთან მუშაობის ცოდნა. უკეთ შევისწავლე JSON მონაცემების სტრუქტურა, მათი წაკითხვა და დამუშავება. ცოდნის გასაღრმავებლად ვუყურე შემდეგ YouTube ვიდეოს და დამატებით შევასრულე რამდენიმე პრაქტიკული დავალება:
- JSON-თან მუშაობა: https://youtu.be/yy-RPsffuKk?si=d-fyvjyNQIPCnnKZ
- პროექტის ერთ-ერთი ახალი საკითხი ჩემთვის Google Gemini AI-ის API-ის გამოყენება იყო. ვისწავლე, როგორ ხდება Gemini მოდელის Python კოდიდან API-ის საშუალებით გამოძახება, API გასაღების მიღება და გამოყენება, ასევე მოდელის პასუხის პროგრამაში მიღება და დამუშავება. ამ პროცესში დამეხმარა Claude AI, რომლის საშუალებითაც უკეთ გავერკვიე ინტეგრირების პროცესში, ასევე გამოვიყენე შემდეგი YouTube ვიდეო:
- Gemini AI-ის API-ის გამოყენება: https://www.youtube.com/watch?v=qfWpPEgea2A
- გარდა ამისა, შევისწავლე საქართველოს ეროვნული ბანკის საჯარო API-ის გამოყენება. ვისწავლე ვალუტის კურსების მიღება, კონკრეტული თარიღის მიხედვით ისტორიული კურსების მოძიება და მიღებული მონაცემების საფუძველზე USD და EUR ვალუტების ლარში კონვერტაცია.


## 6. AI ხელსაწყოების გამოყენება

- პროექტზე მუშაობისას ძირითადად კოდის დამოუკიდებლად დაწერას ვცდილობდი. როგორც ზემოთ აღვნიშნე, Google Gemini API-სთან მუშაობის გამოცდილება არ მქონდა, ამიტომ მხოლოდ განსაკუთრებით რთულ შემთხვევებში ვიყენებდი Claude AI-ს დახმარებას. მას ვთხოვდი შეცდომების (bugs) გასწორებაში დახმარებას, თუმცა ჩემთვის მნიშვნელოვანი იყო არა მხოლოდ შეცდომის გამოსწორება, არამედ იმის გაგებაც, თუ რა იყო მისი გამომწვევი მიზეზი და როგორ შეიძლებოდა მისი თავიდან აცილება.
- ასევე გამოვიყენე Claude AI უკვე დაწერილი კოდის გასაუმჯობესებლად და ოპტიმიზაციისთვის. მიღებულ რეკომენდაციებს განვიხილავდი და ვამოწმებდი, რათა უკეთ გამეგო კოდის მუშაობის პრინციპი და თავადაც შემძლებოდა საჭირო ცვლილებების განხორციელება.
